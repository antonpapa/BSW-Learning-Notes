# [底软测试库] 编写规范

## 1. 测试库编写整体要求概述
- 测试库并非底软核心组件，其在正式交付时会从代码中移除，其作用是集成部分测试逻辑，方便客户和自己验证各个核心组件的功能十分正常。
- 针对某一组件的测试库理论上只允许存在一个对应的测试库文件，针对同一核心组件不同功能的测试逻辑应整合在一个文件内，避免代码冗余，方便项目管理。
- 设计逻辑开关，使测试库可以通过标定量和debugger决定开启和关闭，默认关闭测试库逻辑。
- 编写测试库前需要与模块负责人详细对接，确定测试需求，设计测试逻辑，编写完成后需要与模块负责人进行review。
- 命名规则：函数名和变量名标准化（比如测试库相关开头要写Tlib，表定量结尾需加_C等，详见后续）。
- 提前考虑自动化测试逻辑，暴露对应接口（如ECUtest，Capl）。

## 2. 测试库文件结构规范
- 确定测试库服务的模块，在对应的目录下新建服务该模块的测试库文件夹，以被测模块命名该文件夹（比如Tlf3558x的看门狗模块测试库，就命名为Tlf3558xwd），在该文件夹下新建测试库源文件、头文件、数据源文件和数据头文，后续所有的测试库实现均放在该文件下。
- 确定被测功能属于output还是input，并建立对应主函数用于任务挂载。

## 3. 测试库代码示例
- eg：逻辑开关
- 在编写测试库代码时，需实现开关控制其使能，避免与组件逻辑冲突，默认测试库为关。
```c
// 示例代码
Tlib_Tlfxxxxx_Func_Enable_C

Tlib_Component_Dunc_xxxTest()
{
    if(Tlib_Tlfxxxxx_Func_Enable_C 满足条件 || 某全局量符合条件)
    {
        //主要测试逻辑
    }
    else
    {
        //nothing to do
    }
}
```
## 4. 变量整体命名规则
- 开头表明变量的命名空间
- AUTOSAR组件遵循AUTOSAR标准中定义的组件名
- 测试库：Tlib_组件名_组件对应功能_结尾
- 观测量：驼峰体-> Tlib_Tlfxxxx_Func
- 表定量：驼峰体，结尾加_C -> Tlib_Tlfxxxx_Func_C
- 宏   ：全大写 -> TLIB_TLFXXX_FUNC_MAX
- 严格遵守只在头文件中声明，并且在对应的源文件中定义。
- 跨文件使用的变量需要在前加 extern。
- 不希望被优化的变量 在前需加 volatile。
```c

#ifndef _TLIB_TLFXXX_D_H
#define _TLIB_TLFXXX_D_H
//变量声明
volatile extern uint8 tset_exp;

#endif
```
